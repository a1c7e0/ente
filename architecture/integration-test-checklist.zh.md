# Photos + Locker 集成 APK 验收清单

本文用于合并后的集成 APK 做人工冒烟测试。按 P0 → P2 执行；每项勾选后记录设备、APK 版本/commit、账号类型、结果和复现步骤。用专门的测试账号及少量可恢复的测试照片，先确认照片已备份；不要在生产账号上执行重置、删除或接近配额上限的测试。

## 开测前

- [ ] 确认安装的是本次集成构建，而不是旧 APK：Photos 的开发包名应为 `io.ente.photos.dev.debug`，Locker 的开发包名应为 `io.ente.locker.dev`。两者可以并存；测试前后确认登录的是同一测试账号和同一服务器。
- [ ] 若要测 Locker 与 Photos 共用字节配额，先将集成版 Server 部署到测试环境，再登录集成版 Locker。Server 需在 `/users/details/v2` 返回 `lockerQuotaMode: "sharedStorage"`，Locker usage 返回 `quotaMode: "sharedStorage"`。只有 APK、连官方服务或旧 Server 时，Locker 会沿用旧的独立计数/配额显示；这不能证明共用存储没生效。
- [ ] 准备已上传且归当前账号所有的照片；至少准备一个有可识别正脸的人物，以及同一人的侧脸/单人照。若测身体分组，另备若干同一人不同日期或衣着的全身照，并有不同人物作对照。测试数据用于观察实际结果，不预设模型一定检测或匹配成功。
- [ ] 确认 Photos 已登录并开启 Machine Learning consent，完成初始 ML 索引及账号同步。人物建议、未命名人物和身体分组需要账号模式及已上传文件 ID；匿名本地图库不能覆盖这些功能。启用调试 UI：进入 **Settings → Machine Learning**，连续点该页面标题 7 次，在打开的 **ML debug options** 中启用 **Show ML debug options**。设置页不再提供单独的 ML Debug 入口；集成诊断构建的额外工具位于这个隐藏菜单里的 **ML Lab tools**。

## P0：安装、普通使用与模型下载

- [ ] 安装并启动两款 APK，确认不黑屏，能登录测试服务器；照片/文件列表、预览、上传和下载正常。Photos 集成包与 ML Lab 共用包名，签名相同时会更新原 ML Lab 安装，不是第三个独立图库。
- [ ] 在需要首次下载 ML 模型的安装上启用 ML，确认身体检测和身体 embedding 均有下载状态，共用检测模型只展示一条、不与宠物检测重复下载。模型已下载的安装无需为了测试删除模型。
- [ ] 上传少量新照片，确认正常 ML 能索引；已有照片不会仅因缺少 body 信息就自动触发全库补扫。需要旧照片参与测试时，使用下面的单张/多张显式重算。

## P0：核心人物与建议

- [ ] **人物建议与确认仍由用户决定。** 在 Photos 的 **People / 人物** 页面选择一个人物，再点操作菜单中的 **Review**；用已索引的正脸人物和侧脸单人照片观察候选。合格的高质量侧脸 singleton 可以进入现有人工 Review 建议；点开建议后分别验证接受和拒绝动作按原有流程生效。候选出现与否受照片质量和模型结果影响，未出现时记录照片、索引状态和日志，勿据单张照片判定匹配准确率。
- [ ] **建议不会自动并入人物。** 先记录人物照片数和候选；只运行正常 ML 或手动聚类，不点 Review 接受。同步后确认该侧脸仍是待 Review 项，不会静默加入人物。再分别执行接受、拒绝并同步，确认动作在人物/Review 页面反映出来。
- [ ] **自动创建未命名人物阈值。** 通过 Machine Learning 标题点七次打开 **ML debug options**，找到 **Auto-create unnamed people**。确认初始值为 10 张照片；调到 0 显示 Off，并确认后续正常 ML 运行或手动聚类不新建未命名人物；恢复 10 后，用一个未分配的人脸簇在至少 10 张不同的已上传自有照片中的测试集验证新建行为。同一上传文件 ID 的重复索引或同一照片中的多张脸不能重复计数；照片数以不同上传文件 ID 为准，共享给我的照片不计入。新建只在下一次正常 ML 运行或手动聚类时检查，单次最多创建 10 个。
- [ ] **重复设备/同步的保守收敛。** 仅在可控测试账号上用两台设备同时处理同一批未命名候选，等待双方完成 cgroup/人物同步。确认只对未编辑、自动创建且原始和当前人脸集合完全相同的副本做收敛；手动改名/编辑的人物、部分重叠的人脸集合、旧人物和被身体关联引用的人物均应保留。出现短暂重复可记录为并发窗口；不要要求立即合并，也不要把收敛理解为删除服务端人物记录。
- [ ] **单个人物 Reset。** 在 People 中长按人物头像选中一个有分组的人物，打开操作菜单点 **Reset**，确认对话框点 **Yes, reset person**（以界面本地化标签为准）。确认该人物分组和相关身体 Review 决策清除；同步/刷新后空人物缓存和映射消失。之后正常 ML 运行或聚类只在仍有符合条件的人脸/建议时重新出现，不应残留空人物或旧的身体 Review 状态。

## P0：ML 重置的范围与保留项

> 只用可丢弃的少量测试照片。重置会改动加密 ML 元数据及人物关联；操作前记录照片、人物、检测框和身体分组现状。

- [ ] **选择照片的 ML reset。** 在图库长按选择一张自有、已上传照片，打开选择操作菜单，选 **ML reset**。这些选择项需先在 **ML debug options → Show ML debug options** 打开后才显示。确认人物关联及身体 Review 决策被清掉，而 face/body/CLIP 检测、嵌入和人脸簇保留；若所选照片属于一个人脸簇，该簇作为整体解除人物分配。确认原照片和其他元数据不变，等待正常同步后复查。
- [ ] **选择照片的完整 ML reset。** 对另一张可恢复测试照片，从同一选择菜单选 **ML full reset**，分别测 **Re-calculate later** 和 **Re-calculate now**（两轮测试，避免混淆）。完成后确认该照片的 face/body/CLIP 数据及人物/分组关联按完整重置清除；“now”触发正常重算，“later”不立即重算，之后由正常处理补做。原照片和非 ML 元数据应保留。
- [ ] **所有权/共享边界。** 选择集只要混有非本人所有、共享给我的照片，或尚无上传文件 ID 的照片，就确认选择菜单不提供上述选择照片重置动作。可对比纯自有已上传照片的菜单。不要为测试而删除共享资源。
- [ ] **失败与重试。** 若测试环境可安全模拟单文件元数据读取/写入失败，确认失败文件保留本地绑定/索引清理状态并可重试，其他成功文件不被回滚；记录失败文件和日志。不要用生产账号制造失败。

- [ ] **单张 Re-calculate ML Data 与详情检测入口。** 打开一张自有、已上传照片的查看器菜单，确认 **Re-calculate ML Data** 可见且能触发该照片的正常 ML 重算；对共享给我的照片、未上传照片，确认不出现该项。照片详情页的 **ML detections** 可查看已保存检测；对混合选择（自有+共享或未上传）确认批量 ML reset 项隐藏。

## P1：ML Lab 身体诊断与批量重置

- [ ] **身体检测预览。** 在已打开 **Show ML debug options** 的集成构建中，进入照片详情页打开 **ML detections**。确认已存索引与“有索引但无检测”可区分，脸框绿色、身体框橙色，`*` 标出与脸关联的身体；框和照片缩放一致。分数是检测置信度，不是身份匹配概率。
- [ ] **Run once (no save)。** 在同一诊断页执行 **Run once (no save)**。确认结果只用于当前预览，不写入或同步检测，不触发分组/Review；若 ML 锁忙，记录提示并在空闲后重试。原始身体框中被脸关联规则排除的框可显示为红色试验框。
- [ ] **Reset body review and grouping。** 在 **ML debug options → ML Lab tools** 的重置区执行 **Reset body review and grouping**，确认确认页范围计数针对整个已索引、自有且已上传的图库（含隐藏照片），不受当前相册筛选影响。确认 Review 决策、手工分组拆分和拒绝匹配被清除，身体检测及嵌入保留；脸与 CLIP 索引、原照片不变。
- [ ] **Reset body indexes and re-run。** 在另一轮小测试数据上执行 **Reset body indexes and re-run**。确认身体检测和嵌入清除后重新索引；脸与 CLIP 数据、原照片不变。观察进度及单文件失败报告，失败项可重试。仅清除数据而没有显式重置时，不应自行启动全库历史扫描。
- [ ] **ML detections** 与 **Re-calculate ML Data** 由 **Show ML debug options** 控制，不要求 `enteMLDiagnostics=true`。该参数控制的是隐藏菜单内的 **ML Lab tools**；ML Lab APK 使用独立本地数据库，不能读取 Photos 仅保存在本地的索引，可同步的账号加密元数据仍按正常同步流转。

- [ ] **身体建议的缩略图与预取。** 在身体 Review 候选中确认缩略图突出身体框、框外区域变暗，照片方向/裁剪正确。候选加载较慢时，已准备好的下一候选应先显示，不被慢缩略图卡住；切换候选后操作对应当前显示项。
- [ ] **混合人脸/身体分组及多选拆分。** 准备同一人物既有人工/人脸分配又有身体关联的测试数据。在人物的身体分组图库打开更多菜单 → **Mixed grouping**，确认分析并拆分后，仅身体分组被分区；既有人工分配和人脸分组保留，身体分组不会创建新的人脸身份。再多选该组中的一张或多张照片执行移除/拆分，逐项确认只清理身体操作引入的关联，且原有人脸归属仍在。

## P1：Locker 与 Photos 共用存储（需集成 Server）

- [ ] **同一账本与计量。** 在已部署集成 Server 的测试账号下，分别记下 Photos 和 Locker 的用量。上传一个小文件到 Locker，确认 Locker 按字节显示共同用量，Photos 账号用量也包含该文件；Locker 不再以 100/1,000 个项目或独立 1/10 GiB 总量限制上传。不要使用大文件或把账号推到额度边缘。
- [ ] **Metadata 不收费。** 在 Locker 新建一条纯 metadata 的 Note 或 Credential（不附文件），确认不会增加文件存储字节；加入一个真实小附件后，确认只按实际已计入的存储对象变化。重复创建/同步 metadata 也不应新增存储费。
- [ ] **额度边界与家庭账号。** 如有专用测试配额，验证临近额度时 Locker 上传按共享字节额度拒绝/允许，并验证家庭共享额度及成员上限的行为；测试账号不要用生产额度。记录服务端返回、Photos/Locker 显示值和上传结果。
- [ ] **删除生命周期。** 将测试 Locker 文件移入垃圾箱，确认用量按现有垃圾箱规则暂不提前释放；永久删除/到期清除后，再确认共同用量下降。验证已有 Locker 文件无需重新上传或回填也计入共同账本。
- [ ] **回退兼容。** 在隔离测试环境连接不返回共享模式字段的旧/官方服务，确认 Locker 回到旧配额与计数显示。它只检查兼容回退，不能替代集成 Server 的共享模式验收。

## P2：可选 Web 冒烟

- [ ] 可选：在使用集成 Server 的测试 Web 环境上传/删除 Locker 文件，确认 Web 端现有单文件上限及服务端共享额度预检与最终上传结果一致。此集成 APK 验收不要求 Web 增加 ML 重置控件或浏览器 ML 推理。

## 结果记录

每项记录：`通过 / 失败 / 未测`、设备与系统、APK 包名及版本/commit、Server 版本/commit、账号模式（自有/家庭成员/共享）、测试照片或文件数量、操作前后结果、复现步骤及脱敏日志。失败需保留失败时截图或日志时间戳，并说明是 UI 不符、同步未完成、模型未产出候选，还是服务端返回/计量不符。
